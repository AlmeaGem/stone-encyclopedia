# 編集サーバーと写真の確認

現在の写真選択・一括収集・反映の操作は [初心者向け手順](photo-batch-round-one.md) を参照してください。候補採用と公開用データへの反映は別操作です。

## 非公開の編集画面

`npm run admin` で `http://127.0.0.1:4322/login` に起動します。`EDITOR_PASSWORD` は `.env` または自分の端末の環境変数に設定し、20〜256文字の他サービスと異なるパスフレーズを使ってください。パスワードをチャットやGitへ送る必要はありません。

- 待受は127.0.0.1のみ。公開サイトの `/admin` や `/api` に転送しない。
- 起動時にscryptで派生鍵を作り、比較には定時間比較を使用。
- HttpOnly / SameSite=Strictの1時間セッション。ローカルHTTP用のためSecureは付けず、インターネット上でこのまま稼働させない。
- ホスト名・Origin・Content-Type・CSRFトークンを確認。ログインは15分に5回まで。
- 編集・公開操作をサーバー内で直列化。下書きと公開用ファイルの版が変わったら上書きせず409を返す。
- 公開処理に失敗した場合も下書きを残す。

公開サイトは静的HTMLのみです。編集用のJS・API・セッション・未承認の写真候補・下書きは `dist` に含みません。GitHubでの最終公開承認には、アカウントの2要素認証とPRレビューを使用してください。ブラウザだけで利用できるクラウド管理画面は、別認証・強い認証の構成と合わせてフェーズ2で拡張します。

## 内容の編集

1. 編集対象から「石」「読みもの」「願いのカテゴリ」を選び、項目を開く。
2. 石名・英語名・別名・色・テーマ・品質・伝承・注意などをフォームで編集。
3. 出典は資料名、HTTPS URL、実際の確認日、未確認点を記録。記事は段落ごとの見出し・本文を編集できる。
4. 複雑な配列や分類は「構造化データ」欄でも編集できる。石の固定IDとURLは変更できない。
5. 「下書きを保存」で `.editor/drafts/` へ保存。サイトは変わらない。
6. 内容を確認して「公開用データへ反映」。`src/content/` の該当項目だけを更新。
7. `npm run validate`、`npm test`、`npm run build`、`git diff` で確認し、新サイトのPRで公開を承認。

石の鉱物情報が未確認なら空欄のままにします。表示は未確認になります。記事の新規作成も可能です。価格・購入履歴・有料結果・診断スコアは今回の編集画面では変更せず、フェーズ2で実装します。

## 写真候補を収集

編集画面の「写真候補・ライセンス」で石を選び、Commonsから候補を取得します。CLIでも実行できます。

```bash
npm run images:collect -- s107 s134
```

1回1〜3件の石ID、石ごとに最大10候補、日次上限は初期100回（画面から1〜1000回に変更可能）です。石の英語名・日本語名・別名から最大3検索でWikimedia Commonsの公開APIを照会し、画像の原ページ・撮影者・ライセンス等を `.editor/candidates.json` に保存します。本文・写真の自動公開、AI検索、Google画像検索は行いません。

環境からAPIへ接続できない場合は、日本語のエラーを表示して処理を停止します。候補0件やライセンス不明の状態で写真を捏造しません。有料APIは不要です。今回はこの実行環境からCommonsへの接続が403で制限されているため、実検索からの採用写真は0枚です。パーサー・エラー処理・承認・最適化は隔離したテストで検証します。

## 写真の承認

1. 対象の石IDを確認し、候補を開く。
2. 原ページで石種、名称、撮影対象、処理、実物写真であることを確認。AI生成・書籍の切り抜き・別の石・不明な写真は不採用にする。
3. 撮影者、出典、ライセンス名と公式URL、商用利用、改変、帰属・CC BY-SAの継承条件を確認。
4. フォームの撮影者と画像説明を確認（通常はJSON操作不要）。
5. 「この石IDと撮影対象の一致」「商用利用・改変・帰属・継承の確認」を明示チェック。
6. 「採用」を押す。許可ホストからだけ取得し、JPEG・PNG・WebP静止画をデコード、長辺1440px以下・2MB以下のWebPへ変換。EXIF等は除去。
7. 採用日・固定石ID・ハッシュ・寸法・クレジットを非公開の承認キューへ保存。最後に「承認済みの代表画像をまとめて公開用データへ反映」を押し、ビルドで確認。

原則としてCC0・CC BY・CC BY-SAのみ採用。CC BY-NC・改変禁止・不明なライセンスは採用できません。自動取得されたメタデータだけで権利や石の一致を保証するものではなく、管理者の原ページ確認が必須です。CC BY-SAの画像は派生画像も同ライセンスで扱い、本文全体の権利とは分けます。

外部への画像取得は `upload.wikimedia.org`、`images.unsplash.com`、`images.pexels.com` のHTTPSだけに制限。転送先も毎回確認し、内部アドレスや任意のURLへのサーバーアクセスを防ぎます。独自の利用規約しかない画像は、そのまま上記CCライセンスとみなさず採用しません。Unsplash・Pexelsの自動検索は初期版に含めず、Commonsを先行実装しています。

公開詳細の写真下に撮影者・原ページ・ライセンス・加工・確認日を表示します。写真がない場合は実物ではない色のイメージを表示します。「表示から外す」は石の関連付けだけを外し、元ファイルは削除しません。

候補検索はプロセス間のロックで重複実行を止めます。強制終了したプロセスのPIDが記録されたロックは、再開時に生存確認してから回復します。形式が壊れたロックや別の稼働中プロセスのロックは自動削除せず、停止して確認します。候補や公開写真のファイルは削除しません。日次の検索回数は日本時間で区切ります。

採用画像の最適化済み原本は `assets/approved-images/` に保管します。ビルドでは現在の承認メタデータに一致するものだけを生成用 `public/images/` へコピーします。表示解除や差し替え後の古いファイルは原本に残しても、次の公開ビルドには入りません。既に公開した画像はGit履歴・外部キャッシュに残る可能性があるため、権利の撤回等は別途確認が必要です。
