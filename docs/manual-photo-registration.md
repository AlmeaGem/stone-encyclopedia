# 写真を選んで図鑑へ登録する

写真管理の主操作を手動登録へ変更しました。自動検索は「自動検索・既存候補から選ぶ」の中に残してあります。通常の登録でコードやJSONの編集は必要ありません。

## 操作手順

最新のfeat/phase-one-encyclopediaブランチを取得して管理サーバーを再起動し、今までのローカル管理画面から「写真候補・ライセンス」を開いてください。初めて起動する場合は [管理画面の起動手順](photo-batch-round-one.md) を参照してください。管理画面をGitHub Pagesへ公開する必要はありません。

1. **石を選ぶ**：210種類の石名から選択します。固定IDで保存するため、別の石へ名前だけで自動適用しません。
2. **Macから写真を選ぶ**：ブラウザ標準のファイル選択でJPEG・PNG・WebP（10MB以下）を選びます。選択すると画面内にプレビューが出ます。HEICはMacの「プレビュー」等でJPEGに書き出してください。
3. **出典を入力する**：撮影者、出典ページURL、元画像URL、ライセンス、必要なクレジット補足を入力します。元画像URLは保存用情報で、そのURLから勝手に画像を取得する処理はありません。
4. **条件を確認する**：Commonsは原ページの正確なライセンスとバージョンを選びます。自社撮影と個別許諾をCC0に置き換えません。個別許諾の場合は商用掲載・加工等の許諾内容を非公開の記録欄へ入力します。
5. **プレビューを確認する**：写真、登録先の石名・固定ID、撮影者、出典、ライセンスを照合します。石種と実物写真の一致、利用条件の2つにチェックします。入力内容を変えた場合は確認チェックを外し、再確認を求めます。
6. **「代表写真として採用」を押す**：候補保存から承認までを一度の操作で行います。「この写真を選ぶ」やJSON画面を別途開く必要はありません。この時点では公開用manifestを変更しません。確認に迷う場合は「写真を非公開候補へ追加」で保留できます。
7. **承認済みを一括反映する**：「承認済みの代表画像をまとめて公開用データへ反映」を押します。その後「反映した画像をビルドして確認」で検証できます。

一括反映はローカルの公開用データ更新です。GitHub Desktop等で送信し、最新mainを基点に写真関連の変更だけをPRで確認・マージすると、自動的にプレビューデプロイします。手動で更新する場合はDeploy independent previewの実行元と入力refをともにmainにして、新しくRun workflowを実行してください。古い実行のRe-run jobsは当時のrefで再実行されます。

## 対応する権利の種類

| 種類               | 入力・確認                                                           |
| ------------------ | -------------------------------------------------------------------- |
| Commons CC0 1.0    | FileページURL・撮影者・ライセンスを入力し、実物写真と条件を確認      |
| Commons CC BY      | 2.0 / 2.5 / 3.0 / 4.0を正確に選択。帰属・加工等の条件を確認          |
| Commons CC BY-SA   | 2.0 / 2.5 / 3.0 / 4.0を正確に選択。帰属・継承・加工等の条件を確認    |
| 自分・自社で撮影   | 撮影者と権利保有を確認。CCライセンスへ変更せず権利留保               |
| 個別の商用利用許諾 | 撮影者・商用掲載と加工等の許諾記録を入力。必要な公開クレジットも入力 |

Commons画像ではhttps://commons.wikimedia.org/wiki/File:…形式（またはcuridの固定ページURL）を確認先として求めます。入力したライセンスから正しい公式ライセンスURLを自動設定します。対応外バージョン、非商用・改変禁止・ライセンス不明の画像を、近いライセンスへ置き換えて登録しないでください。

撮影者が不明な場合にアプリが推測して補完することはありません。ユーザー自身の確認が必要です。入力やチェックを行ったことは、外部の権利情報を自動検証・保証したという意味ではありません。

## 出典を失わない保存

公開用の出典ページURL・元画像URL・撮影者・ライセンス名と公式URL・クレジット補足は、アップロード候補から承認、一括反映まで維持します。WebPへの変換やEXIF除去によって、入力した出典情報を消しません。

所有・個別許諾の詳細な記録は.editor/upload-rights/に非公開保存し、公開用manifestへ含めません。採用時には石ID・写真ハッシュ・撮影者・ライセンス・出典等を記録と照合します。異なる出典へ書き換えた場合は採用を止めます。以前に登録した形式の記録も読み込めるようにしています。

既存の候補・承認画像は削除しません。代表写真を変更しても、以前の候補と画像原本は残します。一括反映では承認済みの対象石だけを更新し、他の石の写真は維持します。

## 210種類の登録状況

手動登録フォームの下に、210種類の一覧を初期表示します。登録済み・承認済み／反映待ち・候補あり・写真なし・要確認を表示し、状態で絞り込めます。一覧の石名を押すと手動登録先を切り替えます。件数は保存状態から集計します。

## 検証・スクリーンショット

[PCフォーム（合成テスト写真）](screenshots/manual-photo/form-fixture-1440.png) / [スマホフォーム（合成テスト写真）](screenshots/manual-photo/form-fixture-390.png)

ブラウザのファイル選択へテスト写真を渡し、自動検索を閉じたまま、出典入力・プレビュー・採用・一括反映・登録件数更新まで検証します。Mac実機での操作ではなく、標準ファイル選択を使うChromiumテストです。スクリーンショットは実際の図鑑写真ではありません。

ALMÉA Manager、210種類の本文、既存の写真一覧データ、SQL、公開サイトのnoindex設定には変更を加えていません。管理画面と未承認写真は公開サイトへ配信しません。

検証結果：単体テスト41件、ブラウザテスト46件成功。対応する11種類のライセンス区分（CC0、CC BY/BY-SA各4バージョン、自社撮影、個別許諾）について、出典・元画像URL・撮影者・クレジットの保存、採用、反映を確認しました。確認不足・出典の変更を拒否し、二重反映で件数が増えないことも検証しています。lint・型チェックはエラー／警告0件、本番ビルドと210項目・SEO・内部ファイル分離の監査に成功しました。375・390・430・768・1280・1440pxでフォーム表示を確認しています。
