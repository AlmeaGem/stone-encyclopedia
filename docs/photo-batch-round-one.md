一方、仕組みは次のとおり実装しています。

- 210種類から選択して収集。最初の10種類を選ぶボタンも用意。
- 日本語名・英語名・別名の最大3検索、石ごとに最大10候補。重複IDを除外。
- CommonsのJPEG・PNG・WebP候補。CC0、CC BY 3.0/4.0、CC BY-SA 3.0/4.0を商用・改変可能な候補として分類。その他は要確認で採用不可。
- 写真候補をサムネイルで表示し、クリックで拡大。出典ページ・撮影者・ライセンスを確認。
- フォームで写真を選択・確認し、代表画像として承認。コードやJSONの編集は通常不要。
- 承認済みだけをまとめて公開用データに反映。ビルド確認ボタンも用意。
- 登録済み／候補あり／写真なし／要確認／承認済み・反映待ちを210種類一覧で管理。
- 1秒に1リクエスト以下。日次100検索が初期値、1〜1000回で設定。料金は無料Commons APIのみ。
- ジョブの完了位置をディスク保存し、一時停止・再開・エラー停止・再起動後の再開に対応。同時ワーカーと検索をロック。
- API 429・403・maxlag・通信エラーで停止。無制限の自動リトライはしない。
- ブラウザを閉じても管理サーバーが動いていれば収集を継続。パソコンを終了した場合は起動後に再開。

## 管理画面を開く（最初だけ準備）

管理画面は公開サイトにはありません。**自分のパソコンで起動したときだけ**、そのパソコンのブラウザで `http://127.0.0.1:4322/login` を開けます。このクラウド環境の127.0.0.1を、お客様のパソコンからそのまま開くことはできません。

1. Node.js 24以上とGitHub Desktopをインストールします。
2. GitHub Desktopでstone-encyclopediaをCloneし、ブランチをfeat/phase-one-encyclopediaに切り替えて最新を取得します。Managerは開きません。
3. リポジトリのフォルダーで一度 `npm ci` を実行します。
4. `.env.example` を参考に、フォルダー直下の `.env` に `EDITOR_PASSWORD` を設定します。20文字以上の専用パスフレーズを自分のパソコンで入力してください。チャット・GitHub・スクリーンショットへ載せないでください。
5. 同じフォルダーで `npm run admin` を実行します。起動中はその画面を閉じません。
6. ブラウザで上記のログインURLを開き、設定したパスフレーズでログインします。

以降の収集・選択・承認・ローカルビルドは画面のボタンで操作できます。管理画面を公開サーバーへアップロードしたり、待受を0.0.0.0へ変えたりしないでください。

## 写真を見て選ぶ手順

1. 「写真候補・ライセンス」を開きます。
2. 「最初の10種類を選択」を押します。対象10種類・最大30検索・最大100候補の表示を確認し、「選択した石の収集を開始」を押します。
3. エラーが出たら、表示内容を確認して「停止したジョブを再開」を押します。日次上限の場合は翌日まで待つか、自分で上限を変更します。完了済みの石は再検索しません。
4. 「対象の石」を選びます。写真をクリックすると拡大します。「原ページを確認」で撮影対象・実物写真・撮影者・ライセンスを確認します。
5. 好きな候補の「この写真を選ぶ」を押します。撮影者と画像説明がフォームに入ります。必要なら説明だけ修正します。
6. 別の種類の石、AI画像、イラスト、処理不明などで判断できない写真は採用しません。確認できた場合だけ、石種・実物写真の一致と利用条件の2つにチェックします。
7. 「代表画像として採用」を押します。この時点では非公開の承認キューと画像ファイルだけを保存し、図鑑にはまだ反映しません。
8. 10種類について確認できたら「承認済みの代表画像をまとめて公開用データへ反映」を押します。既存の別の石の写真は保持します。
9. 「反映した画像をビルドして確認」を押します。未承認画像やライセンス不明画像はビルド対象になりません。
10. 問題なく操作できたことを確認してから、次の収集で「210種類を選択」を使用します。最大630検索になるため、日次100回なら上限で停止し、翌日に再開できます。必要なら自分で上限を上げられます。

Commonsの検索結果に必ず5〜10枚あるとは限りません。候補0枚・要確認の石は、そのまま残します。石種の同定や商用利用許諾を、検索結果だけで自動確定しません。

## 図鑑へ公開する手順

「反映」や「ビルド成功」は、インターネット公開とは別です。

1. GitHub Desktopで変更を確認します。写真作業で主に変わるのは `src/content/images.json` と `assets/approved-images/` です。
2. `.env` と `.editor/` はGit対象外です。未承認キュー・パスフレーズを追加しないでください。
3. 作業ブランチへコミットしてPushします。コードを手入力する必要はありません。PR #1はマージしません。
4. GitHubのActions → Deploy independent preview → Run workflowを開きます。
5. 実行元main、入力refはfeat/phase-one-encyclopediaで実行します。
6. 成功後、公開プレビューの図鑑で写真・クレジットを確認します。noindexと販売準備中は維持します。

GitHub Pagesは静的サイトなので、ローカルのボタンだけで安全にGitHubへPushする認証や公開承認までは実装していません。GitHub Desktopと既存ワークフローを使います。APIキーやトークンをチャットへ貼る必要はありません。

## 安全性と保存先

- 非公開：`.editor/candidates.json`、`image-job.json`、`image-budget.json`、`thumbnails/`。Git・公開ビルドの対象外。
- 承認後の原稿画像：`assets/approved-images/<固定石ID>/`。未反映の承認画像はまだ公開ディレクトリへコピーしません。
- 公開対象一覧：`src/content/images.json`。一致確認・権利確認・公式ライセンスURL・撮影者・alt・ハッシュ等をすべて検証。
- 公開画像：manifestにある承認済みだけをビルド時にpublic/imagesへコピー。WebP化・縮小・EXIF削除を継続。
- サムネイルは認証済み同一オリジンAPIを経由し、小画像480px・拡大画像1440px上限でローカルキャッシュ。外部URLを自由入力して取得するAPIではありません。
- 元の210種類の説明、石ID、作品・在庫、Manager、認証設定、SQLには変更なし。
- 採用前のAPIメタデータは仮のライセンス情報です。原ページの帰属・改変・継承条件を必ず確認してください。既存の公開クレジット機能を維持しています。

## 将来スマホから安全に選ぶには

今回の管理サーバーはloopback専用で、スマホから直接接続できません。GitHub Pagesへ管理画面や未承認候補を置く方法は採用しません。

将来は、別の非公開管理サービスを用意し、管理者認証・MFA・権限管理を行うAPIから、非公開Storageの候補を短時間のアクセス権で表示する構成が適切です。ジョブはD1/PostgreSQL等で管理し、承認・履歴・固定石IDを保持します。Cloudflare Access＋Workers＋D1＋非公開R2、または独立Supabase Auth＋RLS＋非公開Storage等が候補です。写真選択後も限定権限のGitHub App等で作業ブランチにだけ変更を作り、公開承認を分離します。
