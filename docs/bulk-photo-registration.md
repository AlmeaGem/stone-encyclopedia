# Macで写真をまとめて仮保存・採用する

今回は**ローカル管理画面**の改善です。Cloudflareへ移行しません。写真公開は従来のGitHub Desktop・GitHub Actionsで行います。PR #1は未マージです。

## 最初に：Macの保存データを保護して更新

1. 起動中の管理サーバーを止めます（起動したターミナルでControl+C）。
2. Finderでプロジェクトフォルダー全体を別の場所へコピーしてバックアップしてください。**`.editor/`、`assets/approved-images/`、`src/content/images.json`を含めます**。FinderのCommand+Shift+ピリオドで隠しフォルダーを確認できます。`.editor/`はGitHubへ送らないでください。
3. GitHub Desktopで `AlmeaGem/stone-encyclopedia` を選び、Current Branchを `feat/phase-one-encyclopedia` にします。
4. `Fetch origin`、続いて `Pull origin`。Changesに未コミットの変更がある／競合で更新できない場合は、**Discard changesやフォルダー削除をせず停止**し、表示されたエラーを確認してください。
5. ターミナルでこのプロジェクトを開き、初回更新時だけ `npm ci`、続いて従来どおり `npm run admin`。既存の`.env`とパスワードはそのままです。秘密情報をチャットに貼る必要はありません。
6. ブラウザで `http://127.0.0.1:4322/login` にログイン。表示が古い場合は再読込し、「写真候補・ライセンス」タブを開きます。

Mac内の`.editor/`はGitに含まれず、Codex環境からあなたの実際の仮保存写真を直接確認できません。新しい画面は**今管理サーバーを起動したフォルダー**の既存候補を読み込みます。違う場所に新しくCloneしたフォルダーでは、元のMacの候補は表示されません。候補が見つからないときも、元の`.editor/`を消したり空で上書きしたりしないでください。

## すでに仮保存した写真をまとめて採用

1. 一番上の **「仮保存画像の一括採用」**に保存済みの候補が並びます。石名・固定IDで絞り込めます。30件ずつ表示し、次のページへ進めます。
2. サムネイルを押すと拡大し、石名・石ID・撮影者・ライセンス・出典を確認できます。
3. 採用したい写真にチェック。「候補を全選択」は現在の絞り込み範囲すべて、「選択解除」は選択を解除します。一度に最大210候補です。同じ石は1枚に絞ってください。
4. 各候補の **写真区分**と**写真説明**を確認します。区分が未設定の古い候補は、実物／イメージ／AI生成を自分で指定してください。名前やファイル名から自動決定しません。
5. 選択した全画像について、石ID・石種・写真区分、出典・利用権限・クレジットを実際に確認して、2つの確認チェックを入れます。
6. **「選択した画像をまとめて採用（確認へ）」**。最終確認画面で対象と除外理由を確認し、**「確認した正常画像を採用」**を押します。
7. 採用済み・失敗・未採用の件数と理由を確認します。撮影者・権利情報が不足する古い候補は、下の単品登録または複数仮保存から正しい情報で追加し直せます。元の候補は削除しません。正常な候補だけが承認済みになります。既存の代表写真がある石は一括操作で上書きできません。
8. **「承認済みの代表画像をまとめて公開用データへ反映（既存写真を保護）」**を1回押します。
9. 必要なら従来の「反映した画像をビルドして確認」を押します。その後、下記のGitHub公開手順へ進んでください。

「採用済み」は直近の一括処理で採用した件数。「未採用（全候補）」は未承認のまま残っている候補全体の件数。「選択内除外」は直近の選択のうち確認不足・重複・既存写真保護などで除外した件数です。

## 新しい写真を10〜30枚まとめて仮保存

1. **「複数画像をまとめて仮保存」**でMacの写真を複数選択。最大30枚、1枚10MB以下のJPEG・PNG・WebPです。HEICはJPEGへ変換してください。
2. 各行で210種類から登録先の石を選びます。初期値は未選択です。ファイル名から石種を確定しません。
3. 実物写真／イメージ写真／AI生成画像を指定し、撮影者、権利の種類、出典、必要なクレジット・許諾記録を記入します。必要なら写真ファイルの差し替えやチェック解除ができます。
4. **「選択した画像をまとめて仮保存」**。各行を順番に保存し、成功・失敗を表示します。失敗した行は入力を保持するので修正して再実行できます。保存済みの行は再送しません。
5. 仮保存できた写真は上の候補一覧に残ります。ブラウザを再読込しても保存済みは失われません。その後は上記の一括採用を行います。

**未保存のファイル選択・入力はブラウザだけにあります**。画面を閉じる前に仮保存してください。未保存のまま閉じようとすると確認します。送信途中で閉じた場合は、管理サーバーの処理が終わってから再度候補一覧を開き、保存された行を確認してください。残りだけを選び直します。サーバー停止時も、すでに仮保存・採用された候補はそのまま残ります。

同じ石の複数候補は比較用に仮保存できますが、代表写真としての一括採用時は重複として除外します。AI生成は専用の権利種別と区分を一致させ、公開画面では小さく「イメージ写真」と表示します。他人の写真は、イメージ写真に加工しても元の出典・利用権が必要です。

## 状態と次の操作

| 表示                 | 意味                                            | 次の操作                     |
| -------------------- | ----------------------------------------------- | ---------------------------- |
| 仮保存               | 写真と権利情報をこのMacへ保存済み。未承認       | 画像・権利・区分を確認し採用 |
| 確認待ち             | 要確認状態の候補                                | 不足情報を確認してから採用   |
| 承認済み・反映待ち   | 確認して採用済み。素材ファイルを保存済み        | 承認済みを一括反映           |
| 図鑑データへ反映済み | `src/content/images.json`と公開用画像へ反映済み | Commit・Push・Actions        |
| 公開サイトへ反映待ち | ローカル反映後の次の作業                        | Actions成功と公開URLで確認   |

**ローカル画面はGitHubデプロイの完了を自動判定しません**。「公開サイトへ反映待ち」は公開確認を促す表示であり、実際の未公開を外部照合した結果ではありません。Actions成功後に公開画面を自分で確認してください。

以前の処理も仮保存候補は自動採用せず、承認済みだけを一括反映します。ジェット・シャーマナイトが未承認のままだった場合は、その段階で止まっていた可能性があります。ただし、あなたのMacの実候補を調べて原因を断定したものではありません。

## GitHub Desktop・Actionsで公開

1. 一括反映後、GitHub DesktopのChangesで `src/content/images.json` と `assets/approved-images/` の追加を確認します。`.editor/`や`.env`が含まれていないことを確認します。
2. 内容を説明するSummaryを入れて作業ブランチへCommitし、`Push origin`を押します。PR #1はマージしません。
3. リポジトリのActions → **Deploy independent preview** → **Run workflow**。
4. workflowの実行元を **main**、入力 `ref` を **feat/phase-one-encyclopedia** にして実行。
5. 成功後、`https://almeagem.github.io/stone-encyclopedia/`を再読込し、採用した石の写真とイメージ表示を確認します。

オブシディアン・キャストライトなど既存写真は一括操作で保持します。将来、単品の既存写真を意図的に変更する場合だけ、従来の単品登録・採用後、「単品で確認済みの既存代表写真を差し替える」を明示的にオンにし、対象名の確認を経て従来の反映ボタンを使います。通常の一括作業ではオンにしないでください。

## 保存・検証の仕組み

- `.editor/candidates.json`は削除・初期化せず、既存の単品アップロードと採用を再利用。
- アップロードは1枚ずつ処理し、10〜30枚を1つの巨大リクエストにしません。再送識別子で同じ保存リクエストの重複登録を防ぎます。
- 確認画面の対象をサーバーへ保存し、候補のrevision、石ID、写真区分、権利記録、既存写真との競合を再検証。候補が別画面で変わっていれば採用せず理由を表示します。
- 採用は1枚ごとに状態を保存し、`.editor/bulk-adoption.json`に結果を記録。再読込時に確認でき、管理サーバーが中断した場合も採用済みは保持します。
- 保存画像のハッシュ・画像形式・加工後サイズは既存のSharp検証を利用します。壊れたファイルは採用せず、他の正常な画像の処理を続けます。
- 一括反映は全対象の画像と権利を検証してから原子的にmanifestを更新します。既存石の代表写真・原本を削除しません。
- ローカル管理画面は引き続き127.0.0.1だけで動作し、一般公開サイトに含めません。スマホ幅の表示・タップ領域はブラウザで確認しますが、今回iPhoneからMacへ遠隔接続する公開URLは作成していません。
