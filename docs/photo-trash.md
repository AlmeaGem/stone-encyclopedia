# 仮保存画像の削除と30日ゴミ箱

対象はMacのローカル「図鑑の編集室」です。PR #1の `feat/phase-one-encyclopedia` へ追加しています。公開サイトの写真を削除する機能ではありません。Manager・Supabase・Cloudflareは変更しません。

## Macで最新版に更新

1. 管理サーバーを起動しているターミナルで **Control+C** を押して停止します。
2. Finderで現在使っているプロジェクトフォルダーを別の場所へコピーしてバックアップします。隠しフォルダー **`.editor/`**、`assets/approved-images/`、`src/content/images.json`を含めてください。隠しフォルダーは **Command+Shift+ピリオド**で表示できます。`.editor/`と`.env`をGitHubへ送らないでください。
3. GitHub Desktopで **AlmeaGem/stone-encyclopedia** を選び、Current Branchを **feat/phase-one-encyclopedia** にします。
4. **Fetch origin → Pull origin**。未コミットの変更や競合が表示された場合は、**Discard changesで消さず**、バックアップを保持してエラーを確認してください。
5. いつも使っている同じフォルダーで `npm run admin` を実行し直します。既存の`.env`とパスワードはそのままです。初期化・SQL実行・新しい契約は不要です。
6. `http://127.0.0.1:4322/login` にログインし、ブラウザを再読込して **「写真候補・ライセンス」**タブを開きます。

Mac内の`.editor/`はGitHubに含まれないため、Codexからあなたの実際の仮保存候補は確認していません。今回、実際の候補を勝手に削除していません。新しい場所にCloneするより、現在の候補が入った元のフォルダーを更新してください。

## 1枚だけ削除

1. 「仮保存画像の一括採用」の候補カード、または従来の石別候補カードにある **「削除」**を押します。
2. 最終確認で石名・固定ID・枚数・サムネイルを確認します。
3. 削除する写真にだけチェックが入っていることを確認し、**「チェックした候補をゴミ箱へ」**を押します。
4. 候補一覧と件数が更新されます。画像原本・権利記録は保持されます。

**「キャンセル」**またはEscapeで閉じると候補は変わりません。承認済み・公開済みなど、対象外のカードの削除ボタンは無効です。

## 複数をまとめて削除

1. 候補一覧で不要な写真にチェックします。「候補を全選択」や石名・IDの絞り込みも使えます。
2. **「選択画像を削除」**を押します。最大210候補ずつです。
3. 最終確認画面のサムネイルと石名を確認します。**ここでもチェックを外せます**。最終確認でチェックした写真だけが対象です。
4. **「チェックした候補をゴミ箱へ」**で実行します。

選択後に候補が編集・承認された場合など、確認内容と実データが違うときは削除全体を中止します。一覧を再読込して対象を確認し直してください。チェックしたもの以外へ対象を広げたり、対象外の画像を巻き込んだりしません。

## ゴミ箱から復元

1. **「候補画像のゴミ箱（30日間復元可能）」**を開きます。
2. 石名・サムネイル・削除日時・復元期限を確認します。日時は日本時間です。
3. 対象の **「復元」**を押し、確認します。
4. 元の仮保存／確認待ち状態で候補一覧に戻ります。**承認・公開はしません**。

復元期限は削除から30日です。期限を過ぎてもこの機能が画像原本を自動消去することはありませんが、画面からの復元は期限内に行ってください。期限後や元の記録が変更されている場合は、JSONを自己判断で書き換えず、バックアップと元のフォルダーを確認してください。

**削除・復元によってディスク容量は減りません**。誤削除対策として原本と権利記録を保持し、完全消去・自動掃除は実装していません。

## 公開操作との違い

- 候補の削除・復元はMac内ですぐ反映されます。**この操作だけならCommit・Push・GitHub Actionsは不要です**。
- `src/content/images.json`、`assets/approved-images/`、公開済みサイト、本文210項目は変更しません。
- 代表写真をサイトから外す操作とは別です。仮保存候補の削除機能から公開済み写真は削除できません。
- 復元後に採用・一括反映して初めて、従来のGitHub公開手順へ進みます。一括アップロード・一括採用・単品採用はそのまま使えます。
- スマホ幅の表示とタップ領域に対応していますが、ローカル管理サーバーは引き続き127.0.0.1だけで動作します。iPhoneから遠隔接続する一般公開URLは追加していません。

## データ保護の設計

候補情報の本体 `.editor/candidates.json` は削除時に書き換えません。`.editor/photo-trash.json` に対象のスナップショットとゴミ箱状態を原子的に記録し、通常の候補一覧から外します。元画像、共有されている画像ファイル、サムネイル、ライセンス・許諾記録は削除しません。新しいアップロードや採用を行っても、ゴミ箱内の元候補は保持します。

最終確認の内容はサーバーが `.editor/trash-previews/` に保存します。実行時に以下を再確認します。

- 対象がこのMacの候補一覧に実在し、識別子が一意であること
- 仮保存または確認待ちであること
- 公開用manifestの代表写真に一致しないこと
- 確認後に候補の内容が変更されていないこと
- 最終確認の対象内で、実行時にチェックした候補だけであること

1件でも不適切な対象が含まれれば、削除状態を書き込まず中止します。同じ削除要求の再送でも重複処理しません。ゴミ箱内の候補を古い画面から採用・編集・アップロード再送して復活させる操作も拒否し、明示的な復元を必要とします。復元時も元記録・利用権記録・アップロード画像のハッシュを照合し、他のデータを上書きしません。

管理ログイン、同一Origin、CSRF検証、サーバーの変更処理の直列化を既存APIと共用します。ゴミ箱や候補データ、管理画面は公開ビルドに含めません。既存の`.editor/`を初期化しません。
