# スフィア優先検索と画像表示の改善

## 状態と比較の限界

今回の環境ではCommons APIとOpenverse公式ドキュメントへの接続がCONNECT応答403で遮断されています。既存の管理画面をご自身のパソコンで動かした際の結果とは別です。**実写真を新規取得して10種類の美しさ・形状・件数を比較する作業は未完了**です。アクセス制限を回避した取得や別サイトへの無断置換は行っていません。

s001〜s010の10種類について、従来の石名だけの検索式とスフィア優先の検索式を比較しました。[比較データ](photo-search-ten-comparison.json)に固定ID・石名・検索式・実接続未検証の状態を保存しています。画面画像は隔離した合成テスト候補を使ったUI比較で、実写真の検索結果とは報告しません。

## 検索の変更

共通の検索選択欄を追加しました。単体収集とバッチ収集の両方に適用し、ジョブにも条件を保存します。

| 選択肢                         | 主な英語検索語                                                                   |
| ------------------------------ | -------------------------------------------------------------------------------- |
| 丸玉・スフィア優先（初期設定） | sphere / crystal sphere / gemstone sphere / polished stone sphere / crystal ball |
| 研磨石・タンブル               | tumbled / polished gemstone / polished stone / gemstone beads                    |
| 宝石ルース                     | gemstone / cabochon / gemstone cabochon / faceted                                |
| 原石・鉱物標本                 | mineral / specimen / rough / crystal                                             |
| すべて                         | 従来同様、石名を中心に検索                                                       |

英語名・日本語名・別名から最大3検索、1回の収集で最大10候補を追加します。希望形状が見つからなくても、別形状へ勝手に切り替えません。既存候補は保存し、過去の候補を10枚に切り詰める旧処理を取り除きました。そのため複数回収集した履歴は合計10枚を超えることがあります。

検索語は形状・石種・実物写真の証明ではありません。新しい候補は必ず「形状未確認」です。写真を見て形状を設定し「候補だけ保存」すると、確認済みの形状別にグループ化・絞り込みできます。石種と利用条件は採用時にも確認が必要です。

## 読み込めない画像

従来は単一のサムネイルURLを読み込み、失敗しても理由を表示していませんでした。実際の不具合URLがこの環境にないため、元の全候補の個別原因は特定できていません。

- HTTP 403・404・429、画像形式、サイズ上限、通信／タイムアウト、画像デコード失敗などの理由をカードに表示。
- 画像が表示できるまで「この写真を選ぶ」を無効化。既知のエラー候補は同じ形状グループ内で後ろへ表示。
- 「画像を再取得」でCommonsの固定ページIDから公式imageinfo APIへ照会し、現行のサムネイルURL・原画像URL・形式・寸法・ライセンス情報を再確認。
- 削除・未対応形式・API制限では停止して説明を表示。403を回避するホスト・プロキシ・無断転載サイトへの切替はしない。
- 再取得は日次上限と1秒以上の検索間隔に含める。無制限の自動リトライはしない。
- URLや利用条件等が変わった候補は再確認が必要な状態に戻す。既存の公開写真一覧を再取得だけで変更・削除しない。
- 同じ画像の同時取得をまとめ、外部画像の取得も直列・1秒以上の間隔に制限。サムネイル生成の集中を避ける。
- 小画像480px、拡大画像1440px上限。認証付きローカルキャッシュを再生成し、拡大側のエラーも表示。

## 品質の見方

Commonsから取得できる原画像の画素数を表示し、同一検索内では高解像度を優先します。アップロードの寸法は最適化後の保存候補です。ピント・自然な色・艶・背景・石の写る割合・透かしは自動判定していません。画面の確認項目に沿って目視し、石名と実物写真の正確性を優先してください。高解像度だけで品質を保証しません。

## 自分の写真・許諾済み写真を追加

1. 対象の石を選び、「自分の写真・商用利用許可を得た写真を追加」を開く。
2. 10MB以下のJPEG・PNG・WebPを選ぶ。HEICは端末でJPEGに変換する。
3. 「自分・自社で撮影」または「商用利用・加工の許諾を取得」を選ぶ。
4. 公開する撮影者名と、非公開の所有・許諾記録を入力する。必要なら公開出典URL・クレジット補足も入力する。
5. 「写真を非公開候補へ追加」を押す。アップロードだけでは公開しない。
6. 候補を選び、石種・実物写真・形状・権利を確認して採用する。
7. 承認済みだけをまとめて反映し、ビルド確認後にGitHubへ送信・既存ワークフローでプレビューを更新する。

所有写真を勝手にCC0へ変更しません。自社撮影は権利留保、個別許諾は個別の商用利用許諾として扱います。許諾の文章や個人情報は.editor内に保存し、公開manifestへ含めません。出典・撮影者・ライセンス・公開クレジット補足は必要に応じて図鑑に表示します。記録を入力しただけで法的な権利が自動検証されたとは判断せず、採用時の明示確認を維持しています。

## 追加ソースの比較（導入前）

| 方法                             | 利点                                               | 導入前に必要な確認                                                                                  | 今回                     |
| -------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------ |
| Wikimedia Commons公式API         | 既存のライセンス情報・固定ページIDを再利用できる   | 各原ページの石種、撮影者、商用利用・改変・帰属・継承条件                                            | 検索と再取得を改善       |
| Openverse公式API                 | 複数提供元の写真を探す候補になり得る               | 現行API利用条件・認証・レート上限、各画像の原提供元・ライセンスの再確認、取得可能な配信ホストの限定 | 条件の実確認待ち。未導入 |
| 自社撮影・個別許諾のアップロード | スフィアの見た目と商品に合う写真を自分で用意できる | 実物の同定、権利保有・商用掲載・加工・クレジット条件                                                | 実装                     |

Openverseは画像そのものの商用利用許諾を一括保証するものとして扱いません。検索でCCと表示されても、原提供元と権利者の確認を必要とします。Getty・ショップ・Google画像検索・無断転載サイトからの自動取得は追加していません。

公式の確認先：

- Commons API： https://commons.wikimedia.org/w/api.php
- Commonsライセンス： https://commons.wikimedia.org/wiki/Commons:Licensing
- MediaWiki API利用作法： https://www.mediawiki.org/wiki/API:Etiquette
- Openverse APIドキュメント： https://docs.openverse.org/api/
- Openverse： https://openverse.org/about/

今回は公式サイトの現行条件をオンラインで検証できていないため、Openverseを安全に導入済み・費用確認済みとは報告しません。新しいAPI契約や課金は行っていません。
