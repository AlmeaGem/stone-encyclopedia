# スペシャルストーン専用テスト画面

既存の無料図鑑には組み込まない、テストWorkerが配信する独立画面です。ログイン・テスト登録、単品と月額のテストCheckout、購入状況の表示、未ログイン・未購入の拒否、購入済み記事・画像を検証できます。テスト用アカウント、テストカード、ダミー原稿とダミー画像だけを使用します。正式な有料素材を入れないでください。

画面は `SPECIAL_STONES_TEST_RETURN_URL` のパスで配信します。同じWorkerオリジンでAPIと画面を配信する前提で、指定するURLのオリジンは `SPECIAL_STONES_PUBLIC_ORIGIN` と完全一致が必要です。いずれも未設定で提供しており、実在する専用テスト画面のHTTPS URLが決まるまでWorkerは503で停止します。本番 `almeagem.github.io` は拒否します。Stripe完了後とキャンセル後はこのテスト画面に戻ります。オリジンは認証の代替ではなく、保護されたAPIは引き続きサーバー側で本人・権限を確認します。

本人確認トークンはタブのメモリーだけに置き、localStorage・sessionStorage・URLへ保存しません。画面再読み込み、Checkoutへ移動した後は再ログインが必要です。ログアウト時は画面内のトークンと表示中の本文・画像を消去します。サーバーで発行済みJWTの即時失効は未実装で、期限まで再利用できる可能性があります。月3回の診断特典も未実装です。

Workerの設定後も、Supabase接続先が本当に専用テストプロジェクトであることは、プロジェクト参照IDとSupabase管理画面を照合して確認してください。`SUPABASE_TEST_PROJECT_REF` と `SUPABASE_APPROVED_TEST_PROJECT_REF` が未設定・不一致なら拒否しますが、同じ値を二重設定しただけでは本番ではないと自動証明できません。Stripeは `sk_test_` のテストモードのみ受け付けます。

実サービスをつないだ操作は未実施です。まずダミーの未購入・購入済みアカウントを用い、Storageの直接URLも両方で拒否されることを確認します。Webhook署名・再送、決済失敗、返金、月額期限切れ、新規記事、解約後の支払い済み期間を実サービスのテストモードで検証します。デプロイ、SQLの適用、秘密情報の入力は別途確認後に行います。

ローカルの画面テストは `TEST_CHROMIUM_PATH=/path/to/chromium node services/special-stones/test/test-screen.browser.mjs` で実行します。既定ではPlaywrightが管理するブラウザを使用します。ネットワーク応答はすべてダミーで、実サービスには接続しません。
